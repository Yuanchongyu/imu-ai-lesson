# 第六课教案：我的动作分类AI（IMU芯片 · 从零搭建的网页版）

> 前置课程：先上完《第五课：我的计步器》，让学生先摸清楚IMU数据长什么样、体验一次"不用AI靠规则解决问题"，再来上这节真正引入机器学习的课。

## 一、课程信息

| 项目 | 内容 |
|---|---|
| 适用对象 | 已上过前几课的学生，8-14岁 |
| 课程时长 | 建议110-130分钟 |
| 所需设备 | XIAO nRF52840 Sense（已烧录 `imu_stream.ino`）+ 一台装了 **Chrome或Edge浏览器** 的电脑（Web Serial功能只有这两个浏览器支持，Safari不行） |
| 所用素材 | 本文件夹里的 `webapp.html`（双击浏览器打开即可）+ `imu_stream.ino`（烧到板子上） |
| 前置知识 | 第一课"训练→测试"的直觉、第二课先导课"传感器→AI处理→决策→执行器"骨架 |

> 设计逻辑：这节课**没有用Edge Impulse这类第三方平台**，而是自己用网页（HTML+JavaScript+TensorFlow.js）把"采集→训练→识别"整条链路搭了出来。好处是所有代码都在一个文件里，学生随时能打开看，不是在操作一个看不见内部的黑箱工具——跟你们做门禁、做导航助手用的是同一种"自己动手搭底层"的态度。

## 二、⚠️ 课前必读：今晚务必自己先跑通一遍

这条流程涉及真实硬件通信（Web Serial），**我没法在你之外的环境里连真实板子测试过**，跟之前几课不一样，这次的风险主要来自"代码没在真实设备上跑过"，务必做到：

- [ ] 电脑装好Arduino IDE，装好Seeed nRF52板卡包和 `Seeed_Arduino_LSM6DS3` 库
- [ ] 把 `imu_stream.ino` 烧到板子上，打开Arduino的串口监视器，确认能看到 `x,y,z` 格式的数字不停跳动（这一步先脱离网页单独确认板子和固件没问题）
- [ ] 关掉Arduino串口监视器（**同一个串口同时只能被一个程序占用**，串口监视器开着的话网页会连不上）
- [ ] 用Chrome打开 `webapp.html`，点"连接XIAO板子"，选中对应的串口，看波形图能不能跟着晃动出现
- [ ] 自己完整走一遍采集→训练→识别，确认整条链路没问题，再带去给学生用

## 三、教学目标

- 能说出这条链路跟之前几课"传感器→AI处理→决策→执行器"骨架的对应关系
- 能解释"为什么不能把原始波形直接喂给AI，要先算出统计特征"

## 四、核心教学洞察（老师自己讲的部分）

### 洞察1：又是同一套骨架

```
拿起板子做动作(传感器) → 网页读取加速度数据(采集) → 神经网络判断(AI处理/决策) → 屏幕显示识别结果(执行器)
```
跟门禁课、导航助手课的骨架又对上了一次。**这次可以问一个更进一步的问题**：
> "前三次我们做的AI，'AI处理'那一步都是找别人训练好的模型（人脸识别模型、Gemini），这次不一样在哪？"

引导学生发现：**这次的模型是我们自己从零训练出来的**，之前几课都是"站在巨人肩膀上直接用"，这次是真正走了一遍"喂数据→模型自己学"的完整过程。

### 洞察2：为什么不能直接把波形丢给AI

打开网页代码里的 `extractFeatures` 函数给学生看：不是把1.5秒里75个点、225个数字原样丢给AI，而是**先算出每个轴的均值、标准差、最大值、最小值、均方根**，一共只留15个数字。

**关键提问**：
> "你觉得为什么要先'总结'一下，不直接把原始数据丢给AI？"

引导学生发现：原始波形每次做动作的具体数值都不一样（手抖一下、快慢不一样），但"这个动作整体是猛烈的还是平稳的""是持续上升还是来回摆动"这种**统计规律**更稳定——这就是"特征工程"，Edge Impulse这类工具的"Spectral Analysis"步骤做的也是同一件事，只是我们这次自己动手算了一遍，而不是让工具在背后偷偷做掉。

### 洞察3："训练"到底在电脑里发生了什么

训练时网页上会画出一条实时下降的损失曲线（红色）和上升的准确率曲线（绿色）。

**关键提问**：
> "红色曲线一直在往下掉，这说明了什么？如果它掉到一半就不动了呢？"

引导学生把"训练"从一个抽象词变成一个看得见的过程：模型一开始瞎猜（损失很高、准确率很低），每看一轮数据就调整一点参数，慢慢地不再瞎猜——这跟先导课"训练=反复做练习题，越做越准"的比喻是一致的，只是这次是眼看着数字在变化，比听比喻更有说服力。

### 洞察4：为什么要"归一化"

代码里有一步 `normalize`，把15个特征都变成"跟平均值差多少个标准差"，而不是直接用原始数值。

**关键提问（可选，适合年龄大一点/理解快的学生）**：
> "如果'最大值'这一列数字天生比'标准差'这一列数字大很多，AI会不会误以为'最大值'更重要？"

引导发现：不同特征的数值范围天生不一样，不处理的话，数值大的特征会"喧宾夺主"，归一化就是让每个特征在AI眼里"公平"地被对待。

## 五、教学环节详解

### 环节1：先看成品（10分钟）

老师现场演示：连接板子→挥动几下→看波形图跳动→现场训练一个"上下甩 vs 左右甩"的简单分类器→做动作让AI认。

**教师话术：**
> "前几节课我们用的AI，都是别人已经训练好的。今天你们要做一件更彻底的事——从零开始，用你自己的动作数据，训练出一个只属于你的AI。"

### 环节2：拆解骨架，对照之前几课（15分钟）

按"洞察1"展开，画出这次的骨架图，跟门禁课、导航助手课的骨架并排对比，讨论"这次AI处理那一步不一样在哪"。

### 环节3：确定动作类别，采集数据（30-40分钟）

学生两两一组，商量出2-4个容易区分的动作（建议幅度大一点，比如"上下甩""左右甩""画圈""突然停住"），每个动作至少录15-20次，鼓励每次做动作时**速度、力度都变化一下**（这个点呼应先导课"训练要用海量、多样的例子"）。

**教师引导提问：**
> "如果你每次录的动作幅度都一模一样，会不会有问题？"

### 环节4：讨论特征提取 + 训练模型（20-25分钟）

按"洞察2""洞察3"展开讨论，点训练按钮，边看着实时曲线边讨论。

### 环节5：实时识别测试（15-20分钟）

学生现场做动作，看AI能不能认出来；鼓励"找茬"——做一个没训练过的动作、动作做得很含糊，观察AI会怎么反应（大概率会把它误分类成某个已知类别，且置信度偏低）。

**教师引导提问：**
> "AI认错的时候，你觉得是它'不知道'，还是它'很自信地猜错了'？看置信度百分比能看出什么？"

### 环节6：总结（10分钟）

回顾四条核心洞察，学生自己复述。

## 六、常见问题与应对

| 情况 | 处理方式 |
|---|---|
| 网页连不上串口 | 先确认Arduino IDE的串口监视器有没有开着占用串口；确认用的是Chrome/Edge不是Safari |
| 波形图不动 | 检查板子有没有正常供电、`imu_stream.ino`有没有烧录成功（打开Arduino串口监视器单独确认一次） |
| 训练完识别效果很差 | 大概率是样本太少或者动作幅度太接近，引导学生重新采集更多、区分度更大的动作 |
| 学生问"这个和Edge Impulse有什么不一样" | 如实说：Edge Impulse是工业界常用的专业工具，功能更强大、更稳定；今天做的是"自己动手搭一遍简化版"，目的是让你们看懂内部原理，两者不冲突，以后想做更复杂的项目可以去用Edge Impulse |
